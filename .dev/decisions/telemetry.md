# Telemetry feasibility decision

Status: synthetic source implemented; opt-in loopback OTLP/HTTP JSON and protobuf sources, bounded source-health reporting, and the first host-ingress authority slice implemented and reviewed (2026-08-02). Live Codex producer compatibility remains open.

## Current decision

The `0.1.0` playable webview uses a deterministic exact synthetic fixture. It is the required token-free QA path and must remain available after real telemetry is introduced.

`src/telemetry/tokenBus.ts` remains the tested normalization/aggregation boundary. `src/telemetry/otlpServer.ts` is now the single production-source adapter: it binds lazily to loopback, accepts bounded OTLP/HTTP JSON or protobuf traces at `/v1/traces` and OTel JSON or protobuf log records at `/v1/logs`, deduplicates span/event IDs, and dispatches validated events from the extension host directly into the active host run. The dependency-free protobuf reader decodes only scalar identities, timestamps, and usage attributes; unknown fields and raw bodies are skipped. Synthetic income is generated by the host run step. Production webviews cannot submit arbitrary token events; only the explicit token-free harness retains a local fixture seam. Completion records retain numeric reasoning-token detail without adding it to total output twice. The host reports disabled/waiting/receiving/error state, accepted event count, last event time, endpoint, and safe startup errors; it never forwards raw content.

`tokenGuild.telemetry.otlpEnabled` is opt-in and defaults to false. `tokenGuild.telemetry.otlpPort` defaults to 4318. Synthetic mode remains explicit and defaults to true for token-free QA; disabling it stops synthetic emission rather than silently falling back to another source. The extension does not treat a webview-submitted token event as an authorized live producer; the first G-01A authority slice now rejects that path and bounds host-applied adapter events.

## Candidate source classification

| Source | Status | Promotion requirement |
| --- | --- | --- |
| Synthetic fixture | Implemented | Remain deterministic, explicit, local, and token-free. |
| OTLP/OTel loopback receiver | Implemented first exact source | Explicit opt-in; JSON and protobuf producer fixtures for `/v1/traces` and `/v1/logs`; loopback-only binding; payload/body limits; port-conflict, remote-host, malformed-input, duplicate, clock/flush, binary wire, and teardown tests; numeric-only reasoning detail; no raw-span retention; accepted events dispatch directly in the host. Official Codex configuration supports OTLP/HTTP `binary` or `json` protocols and documents `codex.sse_event` completion token counts; live producer smoke remains planned in G-06. |
| Explicit API stream proxy | Deferred | User-configured routing, secret redaction, bounded streaming/backpressure, supported-provider fixtures, and clear consent. |
| Document-diff estimate | Deferred estimated source | Measured false-positive/negative behavior, manual-typing exclusion, `estimated` labeling, and no raw text retention. |
| Arbitrary terminal output | Rejected for now | No stable published API/integration has been approved. Do not depend on proposed APIs or scrape terminal content. |

## Required normalized contract

Events retain source, exact/estimated accuracy, timestamp, total output count, optional reasoning-token detail, rate, confidence, optional input/cache counts, agent-active state, and optional run correlation. Exact and estimated counts never merge without provenance; reasoning detail is diagnostic and is never charged twice.

## Privacy and lifecycle gate

Before any real source is enabled:

- no prompt, response, source text, terminal output, authorization header, credential, or raw trace body is persisted or logged;
- observation is opt-in and the UI explains what is collected;
- malformed, duplicate, delayed, oversized, disconnected, and clock-skewed fixtures pass;
- listeners bind to loopback, start lazily, bound memory/work, handle conflicts, and stop on deactivation;
- behavior is tested in the supported local/remote host topology.

## Current source contract (checked 2026-08-02)

The official Codex documentation describes opt-in OTel log export through
`otlp-http` or `otlp-grpc`, with `binary` and `json` OTLP/HTTP protocol values,
and identifies `codex.sse_event` completion records as carrying token counts.
The current extension accepts bounded JSON and protobuf fixtures, but that is
not evidence that a live Codex client is configured to target the extension.
The implementation plan therefore still requires an explicit producer smoke
before claiming live capture. Sources:
[advanced configuration](https://learn.chatgpt.com/docs/config-file/config-advanced#observability-and-telemetry),
[configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference).

P4 review evidence: the OTLP receiver has no raw-body logging or persistence, uses a 1 MiB body/512-span limit and bounded dedupe memory, rejects non-loopback clients and unsupported encodings, and closes on provider disposal or configuration disable. The webview normalizes host timestamps before the shared TokenBus/battery boundary so clock-skewed producer timestamps cannot stall a run. Thinking/error/completion/Berserk gameplay hooks are not part of the normalized path.

## Local producer smoke result (2026-08-02)

The supported local Codex installation was inspected with `codex doctor` and
the user-level `C:\Users\panag\.codex\config.toml`. The configuration contains
model/project settings but no OTLP exporter or telemetry destination, so this
environment cannot prove a live Codex producer-to-extension stream without an
explicit user opt-in configuration. The extension did not modify global Codex
configuration and retains the bounded JSON fixture path as the token-free
fallback. No prompt, response, credential, or private file was read or stored.

## Optional user-level smoke configuration

When the user explicitly wants to test live capture, add this to the user-level
`%CODEX_HOME%\config.toml` (normally `%USERPROFILE%\.codex\config.toml`) while
Token Guild is running with `tokenGuild.telemetry.otlpEnabled = true` and its
port set to `4318`:

```toml
[otel]
environment = "token-guild-local"
log_user_prompt = false
exporter = { otlp-http = {
  endpoint = "http://127.0.0.1:4318/v1/logs"
  protocol = "json"
} }
```

This is a user action, not an extension migration. The endpoint is loopback
only, prompt logging remains disabled, and the extension still retains only
bounded numeric usage metadata. After a smoke run, remove or disable the
exporter and record whether a `codex.sse_event` completion reached the adapter;
never add credentials or headers to the repository. The syntax and exporter
choices follow the [Codex observability configuration](https://learn.chatgpt.com/docs/config-file/config-advanced#observability-and-telemetry)
and [configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference),
checked 2026-08-02.
